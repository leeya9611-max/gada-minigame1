## WP0. 화면 가로(landscape) 전환 [최우선]

목표: 세로 화면의 좁은 전방 시야 문제 해결. 논리 해상도를 가로 800×450(16:9)로 전환하고 가로 고정.
대상: `app/game/engine/config.ts`(VIEW/GROUND), `app/game/Game.tsx`(캔버스·스케일), `app/layout.tsx`(viewport), 스폰 y·지면 좌표 전반.
완료 기준(AC):
- VIEW W=800, H=450, 지면 높이 약 110(GROUND_Y ≈ 340).
- 캔버스가 가로로 렌더되고 기기 가로에 맞춰 스케일(contain, 필요 시 레터박스).
- 세로로 들고 있으면 "가로로 돌려주세요" 안내 또는 CSS 90° 회전 처리.
- 장애물/코인/투척/박소장 스폰 y가 새 지면 기준으로 정상.

```
[클로드코드 프롬프트 — WP0]
게임 화면을 세로에서 가로(landscape)로 전환해줘. 메커닉(좌→우 러닝)은 그대로.
1) config.ts VIEW를 W:800, H:450, GROUND_H:110 으로 바꾸고 GROUND_Y 등 파생값을 재확인해. 점프 물리는 유지하되 화면 높이가 낮아졌으니 코인 스폰 높이 범위(현재 GROUND_Y-30~220)를 새 높이에 맞게 조정해.
2) Game.tsx 캔버스를 800x450으로, 기기 화면에 contain 방식으로 스케일(가로 꽉 차게, 비율 유지, 필요 시 상하 레터박스). touchAction none 유지.
3) app/layout.tsx viewport와 컨테이너를 가로 기준으로. 기기가 세로면 "가로로 돌려주세요" 오버레이를 띄우거나, 불가하면 게임 컨테이너를 CSS로 90도 회전하는 방식 중 웹뷰에서 안정적인 쪽으로 구현해.
4) 모든 스폰/렌더 y좌표가 새 지면(GROUND_Y)에 맞는지 점검.
npm run build 통과 확인하고 실제 플레이(가로)로 검증한 뒤 변경 요약 보여줘.
```

## WP1. 핵심 룰 재정의 (감속=피격 패널티, 다방커피=HP 회복)

목표: 기획서 v2.2 핵심 변경 반영. 감속을 "맞았을 때만" 발생시키고, 다방커피를 회복 아이템으로 전환.
대상: `app/game/engine/config.ts`, `GameEngine.ts`, `player.ts`, `Game.tsx`(HUD 플래그명).
완료 기준(AC):
- 지면 장애물·투척물 **둘 다** 피격 시 HP−1 + 감속(slowUntil) 발생.
- 다방커피 획득 시 감속 없음. 대신 **HP +1(최대 3)**. HP가 이미 최대면 소량 코인/점수로 대체.
- HUD의 `coffeeActive`(슬로우와 혼용) 플래그를 의미에 맞게 정리(예: `slowActive` = 피격 감속 표시).

```
[클로드코드 프롬프트 — WP1]
기획서 docs/야리끼리_대소동_게임기획서.md 5.1/5.6과 이 지시대로 핵심 룰을 바꿔줘.
1) 감속(slowUntil)은 "피격 시에만" 발생하도록 통일: app/game/engine/GameEngine.ts의 handleCollisions에서 투척물 피격에도 지면 장애물과 동일하게 this.slowUntil = now + SPEED.SLOW_MS 를 적용해.
2) 다방커피에서 감속을 제거하고 HP 회복으로 바꿔: coffee 획득 시 player.hp를 1 회복(PLAYER.MAX_HP 상한). 이미 최대면 코인 +3 정도로 대체 지급. player.ts에 heal() 메서드를 추가해서 사용해.
3) config.ts의 ITEM_EFFECT.COFFEE_SLOW_MS 는 제거하고, 필요시 COFFEE_HEAL = 1 상수를 추가해.
4) HUD 상태에서 coffeeActive(슬로우와 혼용된 이름)를 slowActive로 바꾸고 Game.tsx 표시도 "피격 감속" 의미로 맞춰. 커피 대사는 회복 콘셉트("각성! 다시 뛰자")로 바꿔.
변경 후 npm run build 로 타입/빌드 통과 확인하고, 바뀐 파일과 요약을 보여줘.
```

## WP2. 박소장 추격 시스템 (gap 노출 + HP 하이브리드)

목표: 박소장을 화면 뒤편에 상시 노출하고 추격 거리(gap)를 도입. gap 0 = 붙잡힘(게임오버), HP 0과 병존.
대상: `config.ts`(CHASE 상수), `GameEngine.ts`(gap 상태·업데이트·게임오버), `Game.tsx`(추격 게이지 HUD, 박소장 렌더).
완료 기준:
- 시작 gap 180, 상한 260, 안전 주행 시 +25/s 회복, 피격 시 −70.
- 감속(WP1) 지속 동안 박소장이 상대적으로 더 접근하는 체감.
- gap ≤ 0 → 즉시 게임오버("박소장에게 붙잡혔습니다…"). HP 0도 기존대로 게임오버.
- HUD에 추격 거리 게이지 표시. 박소장(현재는 도형)이 플레이어 뒤 `PLAYER.X - gap` 위치에 그려짐. 부스터 중 gap 회복.

```
[클로드코드 프롬프트 — WP2]
기획서 5.3 "Boss System — 추격"을 구현해줘. 실패 조건은 HP 0 또는 gap 0(붙잡힘) 병존(하이브리드).
1) config.ts에 CHASE 상수 추가: START_GAP 180, MAX_GAP 260, RECOVER_PER_SEC 25, HIT_LOSS 70.
2) GameEngine.ts에 this.gap 상태 추가. 매 프레임: 안 맞았으면 gap += RECOVER_PER_SEC*dt (MAX 상한). 피격(장애물/투척) 시 gap -= HIT_LOSS. 감속 중에는 회복을 멈추거나 절반으로. gap<=0 이면 gameOver 호출. 부스터 활성 중에는 gap 회복 가속.
3) Game.tsx: 상단 HUD에 "박소장 추격" 게이지(gap/MAX 비율)를 추가하고, 캔버스에 박소장을 플레이어 뒤(PLAYER.X - gap, 화면 밖이면 가장자리 클램프)로 도형 렌더해줘. gap이 작을수록 붉은 경고 톤.
4) pushHud에 gap을 실어 HUD가 구독하게 해.
빌드 통과 확인하고 변경 요약 보여줘. (스프라이트는 WP4에서 교체하므로 지금은 도형으로.)
```

## WP3. 슬라이드 (입력·모션 + 상단 투척 회피 + 낮은 통과형 장애물)

목표: 점프 외 슬라이드 조작 추가. 상단 투척은 슬라이드로 회피, 신규 "낮은 통과형" 장애물은 슬라이드로 통과.
대상: `config.ts`(SLIDE), `player.ts`(슬라이드 상태·히트박스), `Game.tsx`(아래 스와이프/하단 홀드 입력), `types.ts`/`obstacle.ts`/`GameEngine.ts`(낮은 통과형 장애물, 상단 회피 판정).
완료 기준:
- 아래 스와이프 또는 화면 하단 홀드 시 김반장이 슬라이드(히트박스 높이 약 절반, 최대 0.9초 후 자동 기립).
- 상단 투척(높이 120~170)은 슬라이드로 통과, 서서 있거나 점프하면 피격.
- 신규 장애물 "lowbar"(낮은 통과형): 슬라이드로 통과, 점프하면 충돌.
- 하단 투척·일반 지면 장애물은 기존대로 점프.

```
[클로드코드 프롬프트 — WP3]
기획서 4.3/5.7의 슬라이드를 구현해줘.
1) 입력: Game.tsx에서 화면 하단 영역 포인터다운 또는 아래 방향 스와이프를 감지해 engine.slide() 호출. 상단 탭은 기존 점프 유지.
2) player.ts: sliding 상태와 타이머 추가. 슬라이드 중 히트박스 height를 약 0.5배로 낮추고 y도 맞춰. 최대 SLIDE.DURATION_MS(900) 후 자동 해제. 공중에선 슬라이드 대신 빠른 하강(선택).
3) config.ts에 SLIDE = { DURATION_MS: 900, HITBOX_SCALE: 0.5 } 추가.
4) 장애물: types.ts ObstacleKind에 "lowbar" 추가. obstacle.ts에서 상단이 막힌 낮은 통과형(슬라이드로만 통과)으로 스폰·렌더. GameEngine 충돌: sliding이면 lowbar·상단 투척을 통과, 아니면 피격.
5) 상단 투척(HIGH) 회피 로직을 "점프 금지"에서 "슬라이드로 회피"로 바꿔.
빌드 통과 확인하고 변경 요약 보여줘.
```

## WP4. 스프라이트 적용 (Kenney 에셋 → 캔버스 렌더)

대상: `public/`로 필요한 에셋 이동, 이미지 로더, 각 렌더 지점.
주의: Next는 정적 파일을 `public/`에서 서빙한다. 현재 `assets/`는 루트라 캔버스에서 못 불러오므로 **필요 스프라이트를 `public/assets/`로 복사**해야 함. 원본 `assets/raw`는 그대로 두고 게임에 쓰는 것만.
완료 기준:
- 김반장 run(2프레임 교차)/jump/fall/slide/hurt, 박소장 run/투척, 코인, 장애물, 아이템이 스프라이트로 렌더.

```
[클로드코드 프롬프트 — WP4]
도형 렌더를 assets/ 의 Kenney 스프라이트로 교체해줘. 매핑은 assets/ASSETS.md 참고.
```

대상: `lib/api.ts`, `lib/auth.ts`, 티켓 상태(클라 표시), `app/game/*`(S4 결과, S5 티켓충전).
원칙: 재화 지급·차감은 네이티브 권위. 웹은 표시·결과 전달만(개발명세서 2·5장).
완료 기준:
- 진입 시 티켓 표시, 1플레이=1티켓 소모(클라 표시 기준), 0이면 S5(광고/포인트/초대) 노출.

```

3) S4 결과 화면: 최종 코인·랭크점수·예상 포인트·[공유]·[랭킹 보기]. S5에서 각 버튼은 네이티브 액션 요청 이벤트만 발생.
```

## WP6. 노선(스테이지) 시스템

목표: 엔들리스 스폰 → **노선 데이터(JSON)로 정의된 유한 스테이지**를 로드해 재생. 시작→정류장 도착=완주(승리), 잡힘/HP 0=실패.
대상: `config.ts`(MAPS/노선 목록), `GameEngine.ts`(노선 로더·완주 판정·피날레), 노선 데이터 파일(`public/levels/route1~5.json`).
데이터 포맷: **`public/map-editor.html`(맵 에디터)의 저장 JSON과 동일** — `{id,name,index,cols,cellSize,baseSpeed,speedRamp,terrain[],objects[]}`. objects.type = obs_low/obs_high/obs_air/obs_fall/coin/heart/coffee/dash/magnet, terrain = flat/up/down/gap.
완료 기준:
- 노선 데이터를 읽어 지형(오르막/내리막/구멍)·장애물·아이템·코인을 배치하고 재생(절차적 랜덤 스폰 대체).
- 노선 끝(정류장) 도착 = **완주 성공**, 박소장 잡힘/HP 0 = 실패.
- 노선 75~95%에서 **박소장 피날레 돌진**(경고 후 급가속). 노선 번호↑ = 기본 속도·밀도·박소장 세기↑.
- 5노선(도심재건축/아파트골조/지방산단/야간/지하터널) 각 고유 배경·난이도.

```
[클로드코드 프롬프트 — WP6]
기획서 5.1/5.2/5.15대로 엔들리스를 노선(스테이지) 시스템으로 바꿔줘.
1) 노선 데이터는 public/map-editor.html의 저장 JSON 포맷을 그대로 사용:
   {id,name,index,cols,cellSize,baseSpeed,speedRamp,terrain[](flat/up/down/gap),
    objects[]({col,slot,type})}. type=obs_low/obs_high/obs_air/obs_fall/coin/heart/coffee/dash/magnet.
   public/levels/route1.json ~ route5.json 을 로드하는 로더를 만들어(임시 샘플 1개라도).
2) GameEngine: 절차적 랜덤 스폰을 끄고, 노선 데이터의 col×cellSize 위치에 지형·장애물·아이템·코인을 배치. terrain으로 지면 높이(오르막/내리막/구멍) 반영.
3) 완주 판정: 노선 끝(마지막 col=정류장) 도착 시 '완주 성공'. 박소장 잡힘(gap 0)/HP 0 = 실패.
4) 피날레: 노선 75~95% 구간에서 경고 후 박소장 급가속(돌진). 노선 index가 높을수록 baseSpeed·밀도·박소장 세기 상향.
npm run build 통과, 샘플 노선 플레이로 완주/실패 확인 후 요약.
```

## WP6.5. 월드맵 · 노선 선택 · 별점 · 완주 화면

목표: 인트로→로비 흐름, 노선 선택(월드맵), 별점 클리어, 완주 성공 화면. (기획서 4.2/6장 S1/S1.5/S3a, 5.2.1)
대상: 화면 라우팅/상태, 노선 진행·별점 저장(localStorage 허용), `lib/progress.ts`.
완료 기준:
- **S1 인트로**: 로고·버전·[퇴근 시작] 만.
- **S1.5 로비(월드맵)**: 노선 5개(해금/잠금), 노선별 별점·최고기록, 티켓 잔량, [상점], [선택 시작].
- **해금**: 이전 노선 ★ 이상 클리어 시 다음 노선 해금.
- **별점**: ★완주 / ★★무피격 or 코인 N개 / ★★★ 무피격+목표. 노선별 최고 별점·클리어 타임 저장.
- **S3a 완주 성공** 화면: "퇴근 성공!", 별점 연출, [다음 노선]/[재도전]/[랭킹].

```
[클로드코드 프롬프트 — WP6.5]
기획서 4.2/6장/5.2.1대로 로비·노선선택·별점을 구현해줘.
1) S1 인트로는 로고·버전·[퇴근 시작]만. [퇴근 시작]→ S1.5 로비.
2) S1.5 로비(월드맵): 노선 5개 아이콘(해금/잠금), 노선별 별점·최고기록, 티켓 잔량, [상점], [선택 시작]. 노선 선택 후 시작.
3) 해금: 이전 노선 ★ 이상 클리어 시 다음 노선 오픈. 진행/별점은 localStorage(또는 서버)에 저장.
4) 별점 계산: ★완주, ★★무피격 또는 코인 N개, ★★★ 무피격+목표코인(노선별 목표는 데이터에). 노선별 최고 별점·클리어 타임 저장.
5) S3a 완주 성공 화면: "퇴근 성공!" + 별점 연출 + [다음 노선]/[재도전]/[랭킹]. 실패는 기존 게임오버(S3b).
npm run build 통과, 노선 클리어→해금→다음 노선 흐름 확인 후 요약.
```

대상: 캐릭터 정의, 상점/선택 화면, 선택 저장(localStorage 허용), 포인트 잔액(표시).
완료 기준: 김반장 기본 + 4종(왕고참 조공/신입 청년/안전관리자/여성 반장) 상점 노출·구매·장착. 특성은 코스메틱 우선, 특성 도입은 플래그로 분리.

```
[클로드코드 프롬프트 — WP7]
기획서 5.16/5.10의 캐릭터 상점을 구현해줘.
1) 캐릭터 정의(키/이름/스프라이트경로/가격/특성플래그). 김반장(기본,0) + 왕고참 조공/신입 청년/안전관리자/여성 반장. 아트는 assets/raw의 Kenney Toon Characters로 임시.

4) 게임 시작 시 선택 캐릭터 스프라이트로 김반장 자리를 대체.
```

## WP9. QA · 밸런싱 · 폴리시

목표: 크로스 기기·웹뷰 검증, 수치 튜닝, 최종 폴리시(개발명세서 9장, 기획서 9장).
체크:
- iOS/AOS 웹뷰 제스처(슬라이드 스와이프) 충돌, postMessage 브릿지.
- 저사양 프레임 드랍(delta-time), 웹뷰 종료 시 티켓 롤백.
- 밸런싱: 추격 gap·감속·투척 간격·코인 밀도·티어 임계값 실측 튜닝.
- 관찰 지표 로깅(플레이 횟수, 티켓 소진 패턴, 캐릭터·맵 구매율).

```
[클로드코드 프롬프트 — WP9]
QA·밸런싱 패스를 진행해줘.
1) 웹뷰 제스처(슬라이드) 충돌·postMessage 브릿지·저사양 프레임 확인 항목을 점검하고 이슈를 목록화.
2) 추격 gap/감속/투척 간격/코인 밀도/티어 임계값을 플레이 로그 기반으로 조정 제안(수치 표).
3) 기본 이벤트 로깅(플레이 시작/종료, 티켓 소진, 구매)을 추가해 관찰 지표를 뽑을 수 있게 해.
결과를 요약하고 config 변경안을 제시해줘.
```

## 참고

- 각 WP 완료 후 `npm run build` 통과와 실제 플레이 확인을 기본 게이트로 둔다.
- 재화(포인트/티켓) 지급·차감은 항상 네이티브 권위. 웹은 표시·요청·결과전달만.
- 스프라이트는 WP4에서 일괄 교체하므로 WP1~3은 도형으로 먼저 검증해도 된다.
- 김반장 커스텀 스프라이트(파란 작업복+안전모) 확보 시 WP4 경로 상수만 교체.
