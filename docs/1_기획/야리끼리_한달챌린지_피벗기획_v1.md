# 야리끼리 대소동 — 한 달 챌린지 피벗 기획 v1

2026-07 · 웍스메이트 그로스팀
기준 문서: 기획서 v2.4, 작업지시서 v2, 현재 코드(`app/game/engine`)

## 0. 결론 요약

- 한 달 이벤트 조건에 맞춰 **랭킹 축을 엔들리스 단일 지표로 통일**한다. 노선(스테이지) 5개는 버리지 않고 **온보딩·연습 코스**로 강등한다.
- 랭킹 점수는 한 판 최고기록이 아니라 **일일 베스트 합산 + 주간 리셋**으로 설계한다. 매일 접속해야 순위가 유지되는 구조가 리텐션의 본체다.
- 상위 3명 상품만으로는 4일차에 순위가 고착되고 나머지 전원이 이탈한다. **주간 보상 + 참여 추첨**을 반드시 붙인다.
- 에셋은 신규 제작 대신 **팔레트 스왑(코드) + AI 생성(정적 이미지) + Kenney raw 추가 반입**으로 해결한다. 캐릭터 상점은 컷.

## 1. 왜 뒤집는가

| 현 기획(v2.4) | 이벤트 조건과의 충돌 |
|---|---|
| 스테이지 5노선 + 별점 + 해금 | 클리어 타임 랭킹은 1~2주면 상향평준화. 한 달 내내 경쟁이 안 됨 |
| 맵 테마 5종 | 배경 아트가 map1·map2 뿐. 3종 추가 제작은 한 달 이벤트 대비 과투자 |
| 캐릭터 상점·특성(WP7) | 수집·장기 리텐션용 장치. 한 달 이벤트에선 개발비 회수 불가 |
| 엔들리스 = 전 노선 클리어 후 해금 | 랭킹 본선 진입에 5노선 극한 클리어를 요구하면 라이트 유저(주 타깃 40~60대)가 이벤트에 참가조차 못 함 |
| 상위 랭커 중심 보상 | 상위 3명 상품 단독이면 대다수가 초반에 포기 → 리텐션 목적과 정반대 |

코드 현황: 노선 로더·별점·해금·추격(gap)·슬라이드가 이미 구현 완료. 따라서 스테이지를 전부 들어내는 것이 오히려 재작업이다. 구조는 유지하고 역할만 바꾼다.

## 2. 이벤트 구조 (v1.1 — 모드 2개로 축소)

**이벤트명(안): 야리끼리 한 달 챌린지 — "이번 달, 칼퇴왕은 누구?"**

노선 5개 선택·월드맵을 없애고 로비를 버튼 2개로 줄인다: **[안전교육] [무한 잔업 모드]**

| 모드 | 역할 | 설계 |
|---|---|---|
| 안전교육 (튜토리얼) | 조작 학습 + 완주=퇴근 성공 첫 성취 | 90초 **한 판**. 티켓 미차감, 언제든 재입장. 1회 이수 시 무한 잔업 모드 해금 |
| 무한 잔업 모드 (엔들리스) | **랭킹 본선. 이벤트의 전부** | 티켓 차감, 일일 베스트 합산 랭킹(3장) |

### 2.1 안전교육 구간 설계 (판을 쪼개지 않고 한 판 안의 구간으로)

조작이 점프·이단점프·슬라이드 3개뿐이므로 스테이지 여러 판은 관문만 늘린다. 한 노선 안에서 구간별로 기술을 순서대로 등장시킨다:

| 구간 | 내용 | 안내 |
|---|---|---|
| 1 | 점프 — 웅덩이만 | "탭해서 점프!" |
| 2 | 장애물·이단점프 | "공중에서 한 번 더!" |
| 3 | 슬라이드 — lowbar | "아래로 밀어 슬라이드!" |
| 4 | 투척 회피 — '!' 경고 | "!가 뜨면 피하세요" |
| 5 | 미니 추격 → 정류장 도착 | "퇴근 성공!" 연출 |

각 구간 진입 시 짧은 배너 문구, 신규 요소 첫 등장 시에만 속도 일시 감속. 피격 무한 관용(HP 미감소 또는 즉시 회복)으로 이수율 확보. route1 데이터를 이 구성으로 재편집하면 되므로 개발이 아니라 **맵 에디터 데이터 작업**이다.

- 세계관: 건설 현장의 신규 투입 전 필수 절차가 안전교육 — 타깃(40~60대 근로자)에게 즉시 통하고, 박소장이 교육관 역할로 등장하면 서사도 맞는다. '튜토리얼'이라는 외래어를 노출하지 않는다.
- 판을 쪼개지 않는 이유: 다판 구성 시 실패 시 복귀 지점·티켓 차감 여부·중간 이탈 처리 등 설계 결정이 늘어난다. 실유저 테스트에서 한 판 내 학습이 안 되는 게 확인될 때만 2판 분할을 검토한다.
- 기존 route2~5 데이터·코드: 삭제하지 않고 보관. 이벤트 중반 "주간 보너스 미션" 등으로 재활용 여지.

첫 플레이 동선: 인트로 → 안전교육(90초, 퇴근 성공 체험) → "무한 잔업 모드 개방! 랭킹전 참가" → 첫 세션 안에 랭킹판에 이름이 올라간다.

## 2.5 진입 플로우 (배너 → 게임 → 닉네임)

가다는 웹 기반 — 유저는 로그인 상태로 배너를 누른다. 신원은 세션/토큰(userId)으로 자동 확보되므로 **추가 입력은 닉네임 최초 1회뿐**이다.

```
[가다 앱] 배너/팝업 클릭 (UTM)
   → 게임 진입 (세션/JWT 자동 — 입력 없음)
   → 최초 1회: 닉네임 등록 → 안전교육 → 무한 잔업 모드
   → 재방문: 로비 직행 (서버가 userId로 닉네임·진행 조회)
```

### 닉네임 등록 (타이핑 최소화)

- 가다 프로필에 이름·닉네임이 있으면 **프리필** → [이 이름으로 참가] 원탭
- 없으면 현장 감성 자동 생성("불도저 김씨", "칼퇴 장인" 등) + 주사위(재생성) 버튼 → 타이핑 0으로 등록 가능. 직접 입력도 허용(2~8자, 금칙어 필터)
- 내부 식별은 userId. 닉네임 중복 허용(순위·지급에 영향 없음)
- 변경은 라운드(주) 중 1회 제한 — 추월 알림·명예의 전당 노출과 일관성 유지

### 휴대폰 번호는 받지 않는다

- 신원은 가다 계정이 이미 보유. 상품 지급 본인 확인은 **지급 시점에 계정 기준**으로 처리
- 번호 끝자리라도 수집하면 개인정보 항목 추가 → 동의 절차 필요, 입력 필드 하나만큼 이탈 증가
- 이벤트 참여 동의(닉네임 랭킹 노출 등)는 닉네임 등록 화면에 체크 1개로 통합

### 재방문 판정 원칙

- **서버(userId) 기준.** localStorage 기준 금지 — 웹뷰 캐시 삭제 시 재입력 요구하게 됨
- 진행(안전교육 이수·티어)도 서버 저장으로 이관 (현 lib/progress.ts는 localStorage — 이벤트 전 서버 연동 필요)

### 배너·팝업 운영

| 채널 | 노출 | 내용 |
|---|---|---|
| 팝업 | 오픈 첫 주 + 매주 라운드 시작일, "오늘 하루 안 보기" | 라운드 개막·상품 고지 |
| 배너 | 상시 | **내 상태 기반 문구**: 미참가 "이번 달 칼퇴왕 도전" / 참가자 "현재 17위 — 3판이면 10위권" / 티켓 소멸 임박 알림 |

배너를 정적 홍보가 아니라 개인화 상태 표시로 쓰면 배너 자체가 재방문 장치가 된다.

## 3. 랭킹·보상 설계 (핵심)

### 3.1 점수 구조: 일일 베스트 합산

- 하루 점수 = 그날 플레이 중 **최고 기록 1개** (기존 산식: 코인×10 + 거리÷10)
- 주간 점수 = 그 주 일일 점수의 **합** (월~일)
- 랭킹은 주간 점수 기준. **매주 월요일 0시 리셋 = 4라운드**

효과:
- 하루 안 들어오면 그날 점수 0 → 순위 하락 → **매일 접속이 랭킹 유지의 조건**이 된다
- 몇 판을 하든 그날 베스트만 반영 → "출근길에 한 판"이 성립. 폐인 플레이 강요 없음
- 주간 리셋 → 2주차에 시작한 유저도 우승 가능 → 순위 고착·이탈 방지

### 3.2 보상 3층 구조

> **[법적 검토 진행 중 — 2026-07]** 게임산업법 28조 3호(게임 결과 연동 경품 금지, 로스트아크 2025.11 선례)와 게임제작업 미등록 상태로 인해, 아래 표의 "순위 → 상품/포인트" 연결은 **"참여 → 정액 포인트·추첨 / 순위 → 명예 보상(전당·칭호)"** 구조로 변경될 가능성이 높다. 확정 전까지 보상 내용을 외부 고지하지 말 것. 티켓의 포인트 교환도 이벤트 기간 제외 예정. 상세: 법적검토 체크리스트 8장.

| 층 | 대상 | 보상(안) | 목적 |
|---|---|---|---|
| 월간 | 4개 주간 점수 합산 상위 3명 | 상품 (기존 계획) | 헤비 경쟁 |
| 주간 | 주간 랭킹 상위 10명 | 가다 포인트 소액 | 매주 새 목표, 고착 방지 |
| 참여 | 주 5일 이상 플레이 전원 추첨 N명 | 소액 상품/포인트 | 중하위권 이탈 방지. **리텐션 기여도는 이 층이 가장 큼** |

- 티어(직급 4단계: 조공→기공→반장→야리끼리 마스터)는 그대로. 순위와 무관한 개인 성취 축
- 연속 출석 배율(선택): 3일 연속 일일 점수 ×1.05, 5일 ×1.1. 습관 형성 가속. 구현 여유 없으면 컷

### 3.3 어뷰징

기존 계획(서버 권위, playDuration 대비 coinCount 검증, sessionId 재사용 차단) 유지. 일일 베스트 방식이라 다계정 외 어뷰징 이득이 적다. 상품 지급 전 상위권 로그 수동 검수 1회 추가.

## 4. 리텐션 장치

- **일일 티켓 2장, 자정 리셋·미사용 소멸.** 푸시: "오늘의 퇴근 티켓 2장이 곧 사라집니다"
- **추월 알림**: "김OO님이 방금 당신을 제쳤습니다" — 경쟁심리 직격. 푸시 1순위
- **D-day 카운트다운**: 로비·랭킹 화면에 "라운드 종료까지 D-2" 상시 노출
- **명예의 전당**: 주간 종료마다 상위 3명 닉네임을 앱 배너에 게시. 이벤트 종료 후 월간 top3 게시
- 친구 초대 = 티켓 1장(기존 유지). 초대받은 친구가 첫 플레이하면 양쪽 +1장으로 강화 검토

## 5. 에셋 부족 해결책

원칙: 이벤트용 신규 아트는 "그리지 말고" 코드·AI·기존 소스로 만든다.

### 5.1 팔레트 스왑 — 배경 2종을 6종처럼 (비용: 코드 몇 줄)

map1·map2 배경에 캔버스 필터(hue-rotate, brightness)로 시간대 변주를 준다: 낮 → 노을 → 야간. 주차별로 엔들리스 배경 테마를 바꾸면(1주차 낮 시가지 → 4주차 야간) 에셋 추가 없이 매주 신선함을 준다. 야간은 어둡게 + 가로등 글로우 스프라이트 1장이면 충분.

### 5.2 AI 이미지 생성 — 정적 단일 이미지 전담

애니메이션이 필요 없는 단일 PNG는 AI 생성이 가장 빠르다. ASSETS.md의 "커스텀 필요" 목록이 전부 여기 해당:

| 대상 | 비고 |
|---|---|
| 투척물 3종(서류 뭉치·도면 통·확성기) | 회전은 코드로 처리, 이미지는 1장씩이면 됨 |
| 다방커피 아이템 | 상표권 회피 창작 디자인 |
| 티어 배지 4종(조공·기공·반장·마스터) | |
| 원경: 타워크레인, 골조 건물, 버스 정류장 | 실루엣이라 퀄리티 부담 낮음 |
| 투척 경고 '!' 마크, 이벤트 로고·배너 | |

공통 프롬프트 예: "flat vector cartoon game asset, Kenney.nl style, simple bold shapes, solid colors, no outline texture, white background, single object: [대상]". 생성 후 배경 제거해서 PNG로. 톤이 Kenney 벡터 카툰과 맞는지 기존 스프라이트 옆에 놓고 비교 검수.

### 5.3 기존 소스 추가 반입

- `assets/raw`의 Kenney 원본 zip에 미사용 변형 다수(캐릭터 색상별, Toon Characters, UI 6색상). 여기서 먼저 찾는다
- 부족하면 CC0 소스: Kenney 전체 팩(kenney.nl), OpenGameArt, itch.io CC0 필터, CraftPix 무료 섹션

### 5.4 맵 소스는 문제가 아니다

`public/map-editor.html`이 이미 있어 맵(노선)은 아트가 아니라 JSON 데이터다. route1~5 데이터도 이미 존재. 엔들리스는 절차 스폰이라 맵 데이터 자체가 불필요.

### 5.5 캐릭터는 김반장·박소장 2종으로 끝

캐릭터 상점 컷으로 추가 캐릭터 스프라이트 제작이 통째로 사라진다. 커스텀 스프라이트(gimbanjang_custom, parksojang_custom)는 이미 확보돼 있으므로 추가 캐릭터 아트 수요 0.

## 8. 확정 필요 (팀 결정)

2. 서버 집계 개발 리소스: 일일 베스트 합산 로직의 담당·일정 (네이티브/서버 팀 확인)
