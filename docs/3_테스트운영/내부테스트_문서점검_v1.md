## 2. 빠진 문서 (신규 작성 필요)

### 🔴 A. 게임 사양·운영 정책서 (1~2장 요약본)
모두가 같은 그림을 보게 하는 단일 문서. 현재 이 내용이 기획 v1, config.ts, 작업지시서에 흩어져 있고
서로 다른 버전이 섞여 있음. 포함할 것:
- 모드 2개(안전교육=무료 연습 / 무한 잔업=랭킹전) + 진입 게이트(교육 이수)
- 티켓: 시작 2장, 광고 +1, 출석 보상(7일 주기, 7일차 3장), **일일 리셋 정책은 미구현·미확정**
- 라운드: 2026-07-31(금) 시작, 7일 단위 4라운드, 종료 8/27 (⚠️ 정식 런칭 시 월요일 시작 재설정 예정)
- 점수: 일일 베스트만 인정, 주간 점수 = 일일 베스트 합산, 코인 10점·거리 10px당 1점
- 티어 4단계(조공 0 / 기공 1,000 / 반장 3,000 / 야리끼리 마스터 6,000 — 주간 점수 기준)
- 보상: **현재 세이프 모드**(성적 연동 포인트 표시·교환 숨김) — 법적 검토 결론에 따름
- 어뷰징 방어: 서버 점수 상한(초당 130점), 하루 1회 출석은 서버 차단

### 🔴 B. 네이티브(앱팀) 연동 명세서
앱팀이 이 문서만 보고 연동을 끝낼 수 있어야 함:
- 딥링크: `/game?token=<base64url(JSON)>` — 토큰 스펙(uid/exp), **스킴 미확정(보류 항목)**
- 수신(웹→앱): `GAME_RESULT` payload 전체 필드, `NATIVE_ACTION` 5종
  (watchAdForTicket / exchangePointsForTicket / inviteFriend / shareResult / exitGame / claimAttendanceReward)
  — 각각 앱이 해야 할 일(광고 노출→티켓 지급, 웹뷰 닫기, 시스템 공유 시트 등)
- **지급 권위 원칙**: 티켓·포인트 지급/차감은 전부 네이티브·서버. 웹은 표시+요청만
  (현재 웹에 개발용 로컬 스텁 +1 있음 — 연동 시 제거 필요 지점 명시)
- 검증 방법: `?debug=1` 브리지 디버그 패널 사용법(감지 채널·테스트 발사 버튼·성능 표시)
- 채널: ReactNativeWebView / WKWebView messageHandlers / iframe parent 3종 지원

### 🔴 C. 내부 테스트 계획서 + QA 체크리스트
- 테스트 목적·기간·참여 인원, 버그 리포트 방법(스크린샷+디버그 패널)
- 기기 매트릭스(iOS Safari/Chrome, Android Chrome, 가다 앱 웹뷰 — 저사양 1대 포함)
- 시나리오 체크리스트: 최초 진입(닉네임)→교육 완주→랭킹전→랭킹판 확인→출석 수령→
  설정 토글→회전 안내→일시정지/백그라운드 복귀→티켓 소진→충전
- 알려진 제약 고지: **1기기(브라우저)=1계정, 시크릿 모드 금지, 게스트 기록은 기기 로컬 수명**
- 밸런스 피드백 항목: 평균 생존 시간(목표 60~120초), 난이도 체감, 스와이프 슬라이드 감도

### 🟡 D. 이벤트 운영 런북
- 라운드 전환 확인 절차(매주 금 0시 KST — 자동), 이벤트 시작일 변경 방법(config 한 줄+배포)
- 명예의 전당 게시 절차(주간 종료 시 상위 3명 확인 → 앱 배너), 상위권 수동 검수 방법(Supabase 쿼리)
- 장애 대응: Supabase 다운 시 동작(랭킹 조회 실패=조용히 숨김·점수 유실 가능), 재배포 절차
- 데이터 초기화/시즌 리셋 방법(테스트 데이터 삭제 쿼리)

### 🟡 E. 보상 지급 프로세스 문서 (운영+마케팅)
- 층위별(월간 top3 / 주간 top10 / 참여 추첨) 대상 추출 쿼리·지급 주체·지급 시점·고지 방법
- **법적 검토 결과 반영 필수**: 게임산업법 28조(결과 연동 경품) 이슈로 "참여→정액, 순위→명예"
  구조 변경 가능성 — 확정 전 외부 고지 금지 (피벗 기획 3장 경고 유지)

### 🟡 F. 마케팅 키트
- 이벤트 안내문(앱 공지/배너 랜딩 문구) — 보상 확정 전 버전과 확정 후 버전 분리
- 푸시 문구 세트(기획 4장 초안 활용: 티켓 소멸 알림·추월 알림·D-day) + 발송 정책(빈도)
- 유저 FAQ: 티켓은 어떻게 얻나요 / 점수는 어떻게 계산되나요 / 순위 보상은 / 기기 바꾸면 기록은
- 홍보용 스크린샷·GIF 세트(로비/플레이/랭킹판 — 최신 빌드 기준으로 재캡처 권장)

### 🟢 G. 에셋·라이선스 대장
상업 이벤트이므로 출처 정리 필수:

### 🟢 H. 지표 수집·리포팅 계획

## 5. 권장 진행 순서

1. **이번 주**: A(사양·정책서) + C(테스트 계획서) 작성 → 내부 테스트 착수
2. **테스트와 병행**: B(연동 명세) 앱팀 전달, H(지표 수집기) 연결, 미결정 1~3 확정
3. **오픈 전 주**: D(런북) + E(보상 프로세스) + F(마케팅 키트) 확정본
4. G(라이선스 대장)는 F와 함께 마감

> A·B·C는 기존 문서·코드에 내용이 이미 있어 "취합·정리" 작업입니다(각 반나절 내외).
> 요청 주시면 초안까지 작성해 드립니다.
